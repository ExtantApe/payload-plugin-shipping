# Decisions

Dated decisions for this repo, newest last.

- 2026-11-10: created from the standard repo starter kit.
- 2026-11-10: name approved by the owner: Shipping, `@extantape/payload-plugin-shipping`, EasyPost as the first provider. Built by the kits team, alongside Sample Kits. Design: `docs/architecture/0001-design.md`.
- 2026-11-10: MIT (a general Payload plugin); public from the first push after the audit, which the owner approves.
- 2026-11-10: when a change here adds, removes or renames a collection or field (or changes a type, options, required or a relationship), tell the team that keeps the site's seed data when it merges.
- 2026-11-10: the owner's standing rules apply: an agnostic plugin with optional adapters; public from the first push after the audit; the approved name only; schema changes go to the seed data team ahead of time; no family keyword.
- 2026-11-10 (the kits design and the platform team's review): built with no collections. Carrier errors carry EasyPost's code, never its message text, so an address it echoes can't reach logs or users. Webhook handlers can also come from other plugins at `config.custom.shippingHandlers`.
- 2026-11-10 (security read of 2fcb5d6): a purchase with an unclear outcome (network error, 5xx, unreadable reply, no id or tracking number) fails as `MAYBE_BOUGHT`, never "nothing was bought"; a PO Box or General Delivery address on either side forces USPS; the 7-day window covers refunds too and events dated more than 10 minutes ahead are refused; a handler answer other than handled/unknown gives 500; `buyLabel` asks the hook once per action; address checks return codes only.
- 2026-11-26: the external-call hook allows only `true`. `beforeExternalCall` used to allow a call unless it threw, so returning nothing allowed it and so did returning `false`. From now on only an exact `true` (or a promise of it) allows the call. `false`, nothing at all, `1`, `'yes'`, an object, a throw and a rejected promise all refuse it, and nothing is sent. This changes the documented contract ("throw to refuse") before any release: a hook that only throws must end with `return true`. The type is `boolean | Promise<boolean>`, so a hook that returns nothing no longer compiles.
- 2026-11-26: buy each quote once. `buy` and `buyLabel` claim the quote in a `shipping-purchases` record with a unique key (`provider:mode:shipmentId`) before the carrier is called, written outside the caller's transaction. A bought quote answers its first label; one in flight is refused (`BUY_IN_PROGRESS`); a claim that can't be stored refuses (`NOT_CLAIMED`). The key leaves the rate out, so one shipment gets one label. This replaces "built with no collections" from 2026-11-10: the plugin now has one collection, and the seed data team is told when it merges. An in-memory guard was turned down because it doesn't hold across server instances or restarts.
- 2026-11-26: the purchase request carries an `Idempotency-Key` header (SHA-256 of the shipment id and rate id). EasyPost's documentation, read that day, doesn't describe the header, so the docs here say it's sent and claim nothing more.
- 2026-11-26: a 408 or 429 on a purchase is an unknown outcome, with the timeout, network error and 5xx cases. After an unknown outcome the quote stays locked and later buys answer `MAYBE_BOUGHT` without calling the carrier. Settling it is by hand: look the shipment up with the carrier, use or refund a label that exists, or get a new quote. After a clear refusal the claim is removed, because nothing was bought. A lookup the plugin runs itself is left for later.
